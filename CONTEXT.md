# Словарь Personal Corp OS

Канонические термины репозитория. Только определения, без инструкций и реализации.

## Слои

### Слой управления
Где человек ставит цель, задаёт приоритеты и лимиты и оставляет за собой право сказать «годится». Действует человек.

### Слой правды
Где лежит то, что верно про систему: правила, память, индексы, источники истины. Человек пишет, агент читает. Публичное имя выведено из рабочей формулировки «где живёт правда».

### Операционный слой
Где идёт работа: задачи, очередь, статусы, прогоны, отделы. Агент исполняет, человек принимает.

### Слой наблюдения
Где систему видно: дашборды, метрики, блокеры. Агент собирает, человек смотрит.

## Единицы системы

### Штаб
Папка-точка входа агента и карта всей системы. Не хранит результаты работы и не хранит очередь; знает, где они лежат.

### Отдел
Папка, которая отвечает за один домен и копит по нему артефакты, решения и правила. Живёт рядом со штабом, не внутри него.

### Правила папки
Файл `AGENTS.md` этой папки. Единственный источник правил для агента, запущенного отсюда. Правила папки сильнее общих: при совпадении имён действует то, что названо в папке.

### Словарь отдела
Файл `CONTEXT.md` отдела: слова, которыми человек и агенты называют вещи этого домена, одно слово на одно понятие. Правда о системе: слова даёт человек, агент записывает их и читает перед работой.

### Шаблон
Заготовка папки, содержащая только правду о системе. Артефакты в шаблон не входят.

## Работа

### Правда о системе
Утверждение, которое человек пишет сам и которое остаётся верным между прогонами. Живёт в папке с самого начала.

### Артефакт скилла
Файл, который появляется как результат прогона: план дня, ретро, решение, отчёт. В шаблон не кладётся, потому что пустой артефакт выглядит как правда, но правдой не является.

### Скилл
Записанный повторяемый способ работы. Не хранит состояние задач и не хранит результаты. Подключается ссылкой из правил папки, а не угадывается моделью.

### Скилл штаба
Скилл, который смотрит на систему целиком: срез по всем отделам, план недели, маршрутизация задачи.

### Скилл отдела
Скилл, который работает только внутри своего домена. Общий срез нескольких отделов ему не принадлежит.

### Задача
Работа с ожидаемым результатом и понятным условием завершения.

### Место состояния задачи
Единственное место, где обновляются состояние, следующий шаг и итог. Либо файл задачи, либо запись в трекере. Не оба сразу.

### Три уровня задач
Первый — один файл со списком на сегодня. Второй — день, длительные задачи и история разложены по файлам. Третий — состояние длительных задач в трекере, день остаётся коротким списком со ссылками.

### Приёмка
Решение человека о том, годится ли результат. Возможны три исхода: принял, вернул с причиной, остановил.

### Паттерн
Наблюдение, которое повторилось и поэтому поднимается в правила. Одно исправление — случай, два — правило.

## Роли

### Человек
Ставит цель, выбирает следующий ход, принимает результат.

### Агент
Модель в среде с инструментами, правилами и рабочей областью. Читает правила папки, исполняет, оставляет след.

### Субагент
Отдельная сессия под ограниченную подзадачу. Живёт только в операционном слое: не пишет правду о системе и не принимает результат.
