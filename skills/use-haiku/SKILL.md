# Используй Haiku

Haiku 5.5 — руки и разведчик оркестратора: быстрая, дешёвая, читает и отчитывается. Решения, правки кода, планы и ревью остаются у оркестратора. Скилл только для Claude Code: в других харнесах модель субагента задаётся иначе.

Источники (сверено 22.11.2026): [Prompting Claude Haiku 5.5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-haiku-5-5), [Haiku 5.5 overview](https://platform.claude.com/docs/en/models/haiku-5-5/overview), [Claude Code subagents](https://docs.anthropic.com/en/docs/claude-code/subagents), разборы apidog.com, bettertoken.ai, developersdigest.tech.

## Что отдавать Haiku

| Отдавать | Не отдавать |
|---|---|
| Сбор статуса по серверам по готовым командам (ssh, логи, `pgrep`, БД только на чтение) | Правки кода и канонических файлов |
| Поиск по репо: где определено, кто вызывает, с `файл:строка` | План, архитектура, выбор между вариантами |
| Сводка длинного файла или выдачи веб-поиска, которая не лезет в контекст | Ревью PR, вердикт «готово» |
| Прогон тестов и отчёт только о падениях | Вывод «код не используется, можно удалить» без проверки оркестратором |
| Визуальная сверка кадров и скриншотов по чек-листу | Тексты для людей: посты, письма, сценарии (тексты задач и тикетов можно) |

Цифры: $0.10 / $0.50 за 1M токенов на вход и выход до 100K токенов в запросе, выше 100K — $0.50 / $2.50. Окно 1M, ответ до 128K. Sonnet 5.5 дороже в 20 раз, Opus 5.5 в 40. На Terminal-Bench 4.0 Haiku 39,2 %, Sonnet 70,6 %: сложную агентную работу Haiku не тянет.

## Как вызвать

- В вызове Agent всегда `model: "haiku"`. Без параметра субагент берёт `model` из файла агента, затем `CLAUDE_CODE_SUBAGENT_MODEL`, затем модель сессии — обычно это Opus или Sonnet. Параметр вызова сильнее всех трёх.
- Тип: `Explore` для поиска и сводок (без Edit и Write); для команд по ssh — агент с Bash и эффортом из его файла (`effort: low` или `medium` во frontmatter). Встроенный Explore сам на Haiku не переходит, он наследует модель сессии: `model: "haiku"` нужен и ему.
- Запрет на правки задаёт набор инструментов: Explore надёжнее, чем «не редактируй» в брифе. В Bash запись всё равно возможна, поэтому для разведки по серверам в брифе перечисляются разрешённые команды.
- Проверить, что отработал Haiku: `/tasks` во время работы показывает модель и эффорт. Строка «⚠ This agent switched to …» в начале отчёта значит, что работала запасная модель.
- На облачных провайдерах алиас `haiku` даёт Haiku 4.5: там пишите полный ID `claude-haiku-5-5`.
- Эффорт: `low` для коротких команд и сводок; `medium` для поиска по репо и всего, где больше трёх шагов. Explore берёт эффорт сессии. На `low` Haiku чаще пропускает поиск, бросает работу раньше и не проверяет результат.

## Как писать бриф

Haiku начинает с пустого контекста: разговора и прочитанных файлов она не видит. Explore не получает CLAUDE.md. Всё, что должно соблюдаться, пишется в бриф.

Перед вызовом проверь: можно ли одной фразой сказать, что найти, что вернуть и когда остановиться? Нельзя — работа не для Haiku.

Порядок брифа:

1. **Роль и граница одной строкой**: «Ты разведчик, только чтение. Ничего не меняй, не запускай, не останавливай».
2. **Запреты, которые нельзя нарушить**, списком: «не печатай секреты», «БД только `mode=ro`», «без `pkill`, `killall`, `rm -rf`».
3. **Шаги нумерованным списком с готовыми командами.** Haiku выполняет буквально: выдаст ровно то, что вернула команда. Если в команде стоит `head -c 1500`, остаток файла она не прочитает. Ограничивай вывод так, чтобы нужный факт в него попал, или назови этот факт: «из `index.json` выпиши номера всех записей».
4. **Запасной ход на типичный сбой**: «путь не нашёлся — `find ~ -name X`, повтори».
5. **Сегодняшняя дата и часовой пояс**, если работа связана со временем или с веб-поиском. Пересчёт времени не поручай: дай `TZ=<ваш пояс> date` командой.
6. **Формат отчёта**: по пунктам брифа, факты с `файл:строка` или выводом команды; отдельно «что не проверено»; без догадок. Сводку длинного текста ограничь числом пунктов и заголовками. Формат из брифа перекрывает формат отчёта в файле агента.
7. **Правило остановки**: «Остановись, когда ответил на пункты 1–N. Не предлагай улучшений». Для длинной цепочки шагов добавь фразу из гайда Anthropic: «Keep working until everything asked for is done, and only stop to ask when you can't go on».

Не проси Haiku 5.5 писать ход рассуждений в отчёте («объясни, как думал», теги `<thinking>`). Такой запрос она может отклонить с категорией `reasoning_extraction`. Проси вывод и доказательства.

Для правки кода через Haiku, если её всё же отдал, в бриф обязательно: «перед отчётом прогони настоящую проверку — тесты, сборку или саму изменённую команду; не прогнал — скажи, какую и почему». Без этой фразы на `low` и `medium` она пишет в отчёте «готово» без проверки.

## Приёмка отчёта

Отчёт Haiku — сырьё для проверки. Перед тем как передать дальше:

- Сверь главный факт одной своей командой, особенно если по нему будешь действовать (запуск, закрытие задачи, удаление).
- Пересчёты времени, денег и сумм Haiku делает с ошибками: пересчитай сам.
- «Не нашёл» — повод проверить, не обрезала ли команда вывод.

## Образец брифа

```text
Ты разведчик, только чтение. Ничего не меняй, не запускай, не останавливай.
Не печатай значения секретов; БД открывай только file:...?mode=ro; без pkill/killall/rm.

1. ssh prod 'tail -n 8 ~/app/logs/worker.log'
2. ssh prod 'pgrep -af worker.py || echo no-worker'
3. ssh prod 'ls ~/app/out/' — выпиши имена всех файлов.
4. TZ=Europe/Moscow date '+%Y-%m-%d %H:%M'
Путь не нашёлся — ssh prod 'find ~ -name <имя>' и повтори.

Ответ: по пунктам 1–4, только факты из вывода; ошибку команды — строкой ошибки;
в конце «не проверено». Остановись после пункта 4.
```
