# Куда переносить строки и как переписывать

Справка для шагов 3 и 8 скилла `audit-agent-rules`.

## Строка не своего вида

| Что нашлось | Как узнать | Куда | Что остаётся в `AGENTS.md` |
|---|---|---|---|
| Процедура с шагами | Нумерованный список, «сначала… потом…», команды подряд | Скилл (если повторяется и зовётся фразой) или `docs/<тема>.md` | Маршрут: «X делай через скилл `x`» или «Как делать X: `docs/x.md`» |
| История решений | Даты, «решили», «договорились на созвоне», номера задач, «раньше было» | git: история уже лежит в коммитах | Ничего. Если из истории следует действующее правило, остаётся только оно, без даты |
| Справка | Палитра, шаблон, длинный список, таблица контактов, описание формата | `docs/<тема>.md` | Маршрут: «Палитра и шрифты: `docs/brand.md`» |
| Правило одной подпапки | Строка начинается с «в папке X…», «для файлов X…» | Вложенный `AGENTS.md` этой подпапки | Маршрут: «Правила X: `x/AGENTS.md`» |
| Повтор | Та же мысль в другом месте файла или в другом файле | Одно место: где правило действует шире всего | Ничего во втором месте |
| Жёсткий запрет | «никогда не пушь», «не удаляй» | Настройки агента (разрешения, hook) | Строка-пояснение может остаться |
| Устаревшее | Путь не существует, имя старого инструмента, закрытый проект | Удалить; спорное спросить у человека | Ничего |

Код в файле правил (блок ```` ``` ````) почти всегда часть процедуры или справки. Исключение: команда сборки или проверки, которую нельзя угадать из файлов проекта, остаётся одной строкой.

## Примеры правок

Процедура → скилл:

> Было (8 строк): «Чтобы выпустить пост: 1. Возьми черновик из `drafts/`. 2. Проверь факты. 3. …»
>
> Стало: «Пост выпускай через скилл `publish-post`». Шаги переехали в `.agents/skills/publish-post/SKILL.md`.

История → git:

> Было: «С 12.03 после созвона с Аней решили, что отчёты пишем по пятницам (задача #41)».
>
> Стало: «Отчёт недели готов к пятнице».

Правило подпапки → вложенный файл:

> Было в корне: «В папке `clients/` каждое имя файла начинается с даты».
>
> Стало: строка переехала в `clients/AGENTS.md`, в корне маршрут «Правила клиентских файлов: `clients/AGENTS.md`».

## Новый скилл из процедуры

Папка `.agents/skills/<имя>/` (её видят Codex и другие агенты; для Claude Code нужна `.claude/skills/<имя>/` или ссылка на ту же папку). Внутри `SKILL.md`:

```markdown
---
name: <имя>
description: <Что делает, одним предложением>. Use when <ситуация> or on «<фраза человека>».
---

# <Название>

<Шаги процедуры, перенесённые из AGENTS.md без потерь.>
```

## Вложенный AGENTS.md

Только то, что верно в этой подпапке; корень не повторяется.

```markdown
# <Подпапка>

<Одна строка: что здесь лежит.>

- <граница или правило подпапки>
- <маршрут к файлу или скиллу подпапки>
```

## Описание скилла

Формула: что делает + когда брать или по каким фразам. Одно-два предложения. Главное слово в начале.

| Было | Что не так | Стало |
|---|---|---|
| «Помощник для работы с отчётами» | Не сказано, что делает и когда брать | «Собирает отчёт недели из задач и заметок. Use on «отчёт за неделю», «итоги недели».» |
| «Use when the user wants help» | Подходит под любой запрос, перебивает другие скиллы | Назвать конкретную задачу и фразы |
| Два скилла «пишет посты» и «готовит посты для канала» | Пересекаются: агент берёт случайный | Развести по задаче: один пишет текст, другой публикует готовый; в каждом описании своя фраза-триггер |
| Описание на полстраницы с шагами | Шаги нужны только при работе, а описание читается на старте всегда | Шаги в тело `SKILL.md`, в описании одно-два предложения |

Сумма описаний больше бюджета Codex: сначала сократи длинные описания, потом удали или отключи скиллы, которыми человек не пользуется, и копии одного скилла в нескольких папках.
