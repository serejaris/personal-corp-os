# Конвенция заголовков issue

Справочник уровня 2. Читать, когда создаёшь или переименовываешь issue. Все новые issue, которые создаёт manager, следуют одной формуле — канонический операционный слой для агентов (предсказуемый разбор, поиск, группировка).

## Оглавление

- Формула
- Правила
- Где на самом деле живут метаданные типа
- Подшаблоны для продукта и рантайма
- Примеры
- Антипаттерны

## Формула

```
{объект} — {действие} ({когда / контекст})
```

Видимые доменные префиксы (`product:`, `content:`, `ops:`, `infra:`, `epic:` и т.п.) в заголовке **НЕ** пишутся. Метаданные типа живут в лейблах, дереве родителей, Projects и теле.

| Сегмент | Что | Примеры |
|---------|-----|---------|
| **`{объект}`** | Узнаваемый предмет первым (существительное) | `<трек-A>`, `<продукт> L3`, `<имя-человека> S2`, `<handle>` |
| **`{действие}`** | Глагол + короткий объём | `подготовка к встрече <дата>`, `обработать ответ + интейк + слот` |
| **`{когда / контекст}`** | Дата, окно или неделя в скобках в конце; по желанию | `(до <дата>)`, `(<дата> <время>)` |

## Правила

1. **Без доменного префикса в заголовке.**
2. **`{объект}` — существительное первым** для удобства поиска (группирует все задачи этого трека).
3. **Разделитель — длинное тире (—)** между объектом и действием — визуальный якорь, легко разбирать.
4. **Дата в скобках в конце**, не в середине. Предсказуемое место.
5. **Без эмодзи в заголовке** — засоряют поиск и сортировку.
6. **Старые заголовки с префиксами принимай как легаси-алиасы** при поиске и чтении. Не переименовывай автоматически — только если пользователь явно попросил массовое переименование.

## Где на самом деле живут метаданные типа

| Метаданные | Где |
|------------|-----|
| Тип работы | лейблы (своя таксономия): `type:<work-type>`, `area:<domain>`, лейблы жизненного цикла |
| Иерархия трека | дерево родителей GitHub Sub-issues |
| Видимость на неделе | W-label + место в Project |
| Владелец / источник | репозиторий, Project, поля тела |
| Статус корня / эпика | sub-issues summary + тело; префикс `epic:` не нужен |

## Подшаблоны для продукта и рантайма

| Ситуация | Шаблон | Пример |
|----------|--------|--------|
| Функция бота / воронки / рантайма | `<продукт или поверхность> — <исправленное поведение для пользователя> (<неделя/контекст>)` | `<handle бота> — повторный запрос статуса без сброса очереди (W23)` |
| Разведка эксплуатации / ранбук | `<система> — <операционная возможность или ранбук>` | `<сервис> ops — разовые команды в контейнере через ssh (W23)` |

Если заголовок понятен только со скриншотом, именем человека или историей отладочной сессии — заголовок слишком ситуативный. Детали идут в `## What was done`, `Evidence`, `Updates`; заголовок отражает продуктовый результат.

## Примеры

- `<трек-A> — подготовка к встрече <дата> + бюджет до <дата>`
- `<имя-человека> (<handle>) — обработать ответ + интейк + слот`
- `<продукт> L3 — финальная подготовка к лайву (<дата> <время>)`
- `<канал> — пост-итог <месяц> ГГГГ`

## Антипаттерны

- ❌ `🔥 <трек>: КП` — эмодзи + доменный префикс
- ❌ `подготовить встречу <дата> по <трек>` — сначала глагол вместо существительного
- ❌ `ops: всё про <событие>` — доменный префикс + слишком общо, нет конкретного действия
- ❌ `partner: <трек> → расхождение ⚠️ просрочено` — префикс, стрелка вместо длинного тире, эмодзи
