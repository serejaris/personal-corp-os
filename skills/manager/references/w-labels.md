# Правила W-label

Справочник уровня 2. Читать, когда ставишь или проверяешь недельный лейбл. Пропусти весь файл, если конвенция W-label выключена в твоём конфиге.

## Оглавление

- Определение текущей недели
- Issue с датой — W-label по дате события
- Week drift и Project drift (режим чтения)
- Задачи на несколько недель
- Бэклог и будущая неделя
- Создание и добавление W-label — быстрый путь

## Определение текущей недели

1. Прочитай в индексе задач первую строку под твоим маркером «Updated» — канонический сигнал текущей недели.
2. Вычисли ISO-неделю через `date '+%V'`, если индекс устарел (>7 дней).
3. Переведи в формат лейбла: `W{NN}` (с ведущим нулём, только если существующие лейблы в репозитории с ведущим нулём — сначала проверь репозиторий).

## Issue с датой — W-label по дате события

Для issue, у которых в заголовке, теле или календаре есть конкретная дата события (сессия, лайв, воркшоп, дедлайн), W-label считается от **даты этого события**, а не от даты синка.

- `<человек> S2 — подготовить и провести сессию (29.05)` на 2026-05-29 получает `W22`.
- Если в заголовке только `ДД.ММ`, год бери из тела, календаря или контекста текущей сессии. Если год неоднозначен — покажи `Week ambiguity: дата в <repo>#N неоднозначна; в GitHub не пишу до уточнения` и останови запись лейбла.
- Если синк идёт не в ту неделю, что событие, покажи обе: `event week: W22`, `sync week: W23`.
- Если у существующего issue с датой W-label устарел или отсутствует, покажи: `Week drift: <repo>#N «заголовок» — есть <лейблы>, должен быть W{NN}; действие: добавить W{NN}`.

## Week drift и Project drift (режим чтения)

Это два независимых состояния — у issue может быть одно без другого:

- **Week drift:** у issue W-label, который не совпадает с текущей календарной неделей работы → `Week drift: у issue W{NN}, по дате ожидается W{MM}; действие: добавить W{MM}`
- **Project drift:** у issue верный W-label, но его нет на ожидаемой доске Project → `Project drift: W{NN} есть, нет в <Project>; действие: добавить в Project после правки W-label`

Перечисляй оба в разделе Track health вывода режима чтения.

## Задачи на несколько недель

Если задача требует действий на этой неделе И продолжается на следующей — ставь ОБА W-label. Индекс показывает «что горит сейчас»; лейблы записывают весь жизненный цикл.

## Бэклог и будущая неделя

- Если задача **отложена больше чем на 1 неделю** без активной работы → `backlog` (создай лейбл, если его нет).
- Если задача **запланирована на конкретную будущую неделю** → `W{NN}` этой недели.
- Никогда не ставь `backlog` И `W{NN}` вместе — выбери одно.

## Создание и добавление W-label — быстрый путь

Не вызывай сначала `gh label list`, чтобы проверить существование. Сразу пробуй добавить; только при ошибке создай лейбл и повтори:

```bash
gh issue edit <N> -R "$REPO" --add-label "W{NN}" \
  || { gh label create "W{NN}" -R "$REPO" --color "0E8A16" --description "Week {NN}"; \
       gh issue edit <N> -R "$REPO" --add-label "W{NN}"; }

# лейбл backlog
gh label create "backlog" -R "$REPO" --color "ededed" --description "Deferred — not on current/next week"
```

Цвет `0E8A16` (тёмно-зелёный) — для активных недель, `ededed` (нейтральный серый) — для бэклога. Старые `retro:W*` и исторические `W*` лейблы никогда не удаляются ради порядка.
