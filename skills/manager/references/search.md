# Поиск существующих issue

Справочник уровня 2. Читать перед любым поиском issue в обоих режимах: ключи поиска, критерий совпадения, пакетный GraphQL и его обязательные защиты в `jq`.

## Оглавление

- Как искать
- Пакетный поиск через GraphQL (3+ ключа)
  - ВАЖНОЕ — отдельный `jq`, не флаг `--jq`
  - Обязательные защиты в jq
  - Частичные ошибки
  - Почему так

## Как искать

Для каждого артефакта или предмета запроса ищи по **нескольким ключам**, чтобы не пропустить совпадения. Для простых однозначных треков (одно ключевое слово) хватает одного запроса — переходи на несколько ключей, только когда первый запрос вернул 0 или 5+ совпадений:

```bash
gh search issues --owner $YOUR_OWNER <key> --json repository,number,title,labels,state,updatedAt
```

**`--state` принимает только `open` или `closed` — значение `all` недопустимо и падает с ошибкой.** Чтобы охватить оба состояния, просто опусти `--state`: один вызов вернёт открытые и закрытые вместе. Никогда не запускай два запроса (open + closed) — это тратит скудную квоту REST (30 в минуту).

**Ключи, которые стоит попробовать (на артефакт или предмет):**
- Имя человека + slug (разные транслитерации): `"<имя-человека>"`, `<handle>`, `<slug-файла>`
- Компания / трек: `<трек-A>`, `<трек-B>`, `<клиент>`
- Telegram- или соцсетевой handle, если упомянут: `<handle>`
- Slug файла из любого артефакта CRM: `<slug-возможности>`

**Критерий принятия совпадения:** заголовок или тело issue ссылается на того же человека, компанию или трек И объём работы пересекается. Если подходят 2+ кандидата — выбери самый конкретный, остальные свяжи как `Related`.

## Пакетный поиск через GraphQL (3+ ключа)

Когда поиску по нескольким ключам нужно 3 и больше запросов, собери их в один вызов GraphQL, чтобы не упереться в лимит REST Search API (30 запросов в минуту):

```bash
gh api graphql -f query='
query {
  s1: search(query:"user:$YOUR_OWNER is:issue <term1>", type:ISSUE, first:20){ nodes { ... on Issue { number title state url repository{nameWithOwner} labels(first:10){nodes{name}} updatedAt } } }
  s2: search(query:"user:$YOUR_OWNER is:issue <term2>", type:ISSUE, first:20){ nodes { ... on Issue { number title state url repository{nameWithOwner} labels(first:10){nodes{name}} } } }
}' | jq -r '(.data // {}) | to_entries[] | .key as $k | (.value.nodes // [])[] | select(.number != null)
  | "\($k) \(.state) \(.repository.nameWithOwner)#\(.number) \(.title) [\([(.labels.nodes // [])[].name]|join(","))]"'
```

Не ставь квалификатор `state:` — один алиас вернёт и открытые, и закрытые. Добавленный `state:open` молча выбрасывает закрытые issue (например, закрытый эпик), и приходится тратить второй пакет.

### ВАЖНОЕ — отдельный `jq`, не флаг `--jq`

Это причина №1 повторяющихся падений в этом скилле:

- Когда ответ GraphQL несёт массив `errors` (один упавший алиас или полностью сломанный запрос), `gh api graphql` **полностью игнорирует флаг `--jq`**: выводит сырое JSON-тело в stdout плюс короткую ошибку в stderr, код выхода 1. Защита `(.data // {})` внутри `--jq` не выполняется — флаг обходится.
- Полный провал → тело `{"errors":[...]}` без ключа `data`. Любое последующее `d['data']` (Python) бросает `KeyError: 'data'`.
- Поэтому всегда `gh api graphql -f query='...' | jq -r '(.data // {}) | ...'`. Сырое тело (с `data` или только с `errors`) идёт из stdout в `jq`, защита `(.data // {})` срабатывает на теле: живые алиасы печатаются, упавшие пропускаются, полный провал даёт пустой вывод без падения. Ошибка `gh` остаётся видна в stderr для отладки.
- **Никогда не разбирай ответ однострочником на Python (`python3 -c "d['data']..."`).** Если без Python никак, используй `d.get('data', {})`, никогда `d['data']`.

### Обязательные защиты в jq

Без них выражение падает на `cannot iterate over: null`:
- `(.data // {})` **первым** — на теле только с `errors` `.data` равен `null`, и `to_entries[]` падает; `// {}` даёт пустой объект
- `(.value.nodes // [])` и `(.labels.nodes // [])` — алиас или поле может вернуть `null`
- `select(.number != null)` — отбрасывает пустые объекты `{}` от узлов, которые не Issue
- `is:issue` в каждой строке запроса — исключает PR

### Частичные ошибки

С `| jq` упавший алиас просто отсутствует в выводе, а живые печатаются. Не повторяй вслепую весь пакет — при необходимости прочитай `.errors` отдельным проходом (`... | jq '.errors'`), потом убери или почини упавший алиас.

### Почему так

`gh search issues` — это REST Search API с лимитом 30 запросов в минуту: прогоны по нескольким ключам из 15–20 поисков упираются в лимит. GraphQL `search()` расходует лимит GraphQL в 5000 очков в час и эффективно собирается в пакеты. Квалификатор владельца в GraphQL — `user:$YOUR_OWNER` (не `--owner`).
