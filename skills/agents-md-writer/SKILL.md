# AGENTS.md Writer

Скилл пишет и чистит файл правил папки. Файл правил один, и это `AGENTS.md`. Его читают Codex, omp, Cursor, Copilot и Claude Code (с версии 2.1.277, если в папке и выше нет `CLAUDE.md`).

## Что скилл создаёт

| Создаёт | Не создаёт |
|---|---|
| `AGENTS.md` в корне папки | `CLAUDE.md`, `CLAUDE.local.md`, `.claude/CLAUDE.md` |
| Вложенный `AGENTS.md` в подпапке со своими правилами | `.claude/rules/` и поле `paths:` |
| Справку в `docs/`, если строке нужна длинная расшифровка | Импорты `@AGENTS.md` |

Если в папке или выше лежит `CLAUDE.md`, Claude Code читает его вместо `AGENTS.md` и не видит вложенные `AGENTS.md`. Поэтому найденный `CLAUDE.md` скилл сливает в `AGENTS.md` и удаляет, после подтверждения пользователя. Исключение: если у кого-то из пользователей папки Claude Code старше 2.1.277, оставить симлинк `CLAUDE.md → AGENTS.md`. Отдельного текста в нём быть не должно.

Найденную папку `.claude/rules/` скилл разбирает: правило одной папки уходит во вложенный `AGENTS.md`, справка в `docs/`, процедура в скилл. Когда папка опустела, удаляются и `.claude/rules/`, и пустая `.claude/`. `.claude/rules/` читает только Claude Code, остальные харнесы её не видят.

## Три вида строк

Каждая строка файла правил относится к одному из трёх видов.

| Вид | Что делает | Пример |
|---|---|---|
| Маршрут | Ведёт к файлу или скиллу под задачу | «Пост в канал пиши через скилл `telegram-post`» |
| Граница | Что можно и что нельзя | «`_archive/` только читать» |
| Постоянное поведение | Действует на любой запрос | «Отвечай по-русски» |

Строка другого вида уходит из файла:

| Что нашлось | Куда |
|---|---|
| Процедура с шагами («как сделать работу») | скилл или `docs/`, в файле остаётся маршрут |
| История: даты, «решили на созвоне», номера задач | git, в файле не остаётся ничего |
| Правило одной подпапки | вложенный `AGENTS.md` этой подпапки, в корне строка-маршрут |
| Справка (палитра, шаблон, длинный список) | `docs/`, в файле строка-маршрут |
| Правило, верное в любой папке | раздел «Глобальные правила» в `AGENTS.md` штаба, но только если папка — отдел и строка там уже есть или пользователь согласился её туда перенести. Иначе строка остаётся в файле |
| Жёсткий запрет, который нельзя доверить модели | настройка харнеса (`~/.claude/settings.json`, hook, sandbox) |
| Стиль кода | конфиг линтера или форматтера |

Проверка каждой строки: если её удалить, агент ошибётся? Если нет, строка лишняя. Второй фильтр: строка верна для любой задачи в этой папке?

## Размер и цепочка

| Ступень | Ориентир |
|---|---|
| Старт | 40–60 строк |
| Потолок | 200 строк и не больше 32 КБ |

Цепочка файлов правил: все `AGENTS.md` от корня репозитория до папки, где запущен агент. Codex читает их вместе с общим бюджетом 32 KiB (`project_doc_max_bytes`), бюджет считается в байтах UTF-8. Файл, который не влез, обрезается, дальше Codex не читает. Кириллическая буква занимает 2 байта, русский файл правил весит примерно в полтора раза больше английского той же длины: в 32 КБ помещается около 200–300 русских строк. Толстый корень отнимает бюджет у вложенных файлов.

Проверка: `wc -l -c` по каждому файлу самой длинной цепочки, сумма байтов меньше 32 768.

## Вложенные файлы и маршруты

- Вложенный `AGENTS.md` гарантированно читается только в сессии, начатой в его папке. Поэтому в корневом файле обязательна строка-маршрут: «Правила уроков: `programs/AGENTS.md`».
- Вложенный файл не повторяет корень. В нём только то, что верно в этой папке.
- Строка-маршрут называет задачу и путь: «Для X открой Y».

## Штаб, отдел, папка харнеса

| Папка | Первая строка и содержимое |
|---|---|
| Штаб (`hq/AGENTS.md`) | Карта отделов и раздел «Глобальные правила»: строки, верные в любой папке |
| Отдел | Первая строка: «Глобальные правила и карта отделов: `../hq/AGENTS.md`». Дальше правила отдела |
| Проект внутри отдела | Правила проекта; маршрут к штабу, если проект живёт вне дерева штаба |
| Папка харнеса (`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`) | Только строка-ссылка на штаб и то, что касается одного этого харнеса |

Строку про штаб пишут, только если папка — отдел: штаб `hq/` лежит рядом с ней, а путь из первой строки открывается. Папка вне дерева отделов (временная, чужой репозиторий) строку про штаб не получает.

## Шаблон

```markdown
# <Имя папки>

<Одна строка: что это за папка и для кого.>
Глобальные правила и карта отделов: `../hq/AGENTS.md`

## Карта

| Задача | Куда |
|---|---|
| <задача> | `<путь>` или скилл `<имя>` |

## Границы

- <что можно и что нельзя>

## Поведение

- <тон, язык, формат ответа>
```

Строку про штаб пишут только в отделе. В репозитории с кодом в карту идут команды сборки и тестов, которые нельзя угадать из кода.

## Порядок работы

**Новая папка.**
1. Осмотреть дерево: какие подпапки, скиллы, `docs/`, есть ли рядом штаб.
2. Спросить пользователя о границах и поведении, которые не видны из файлов.
3. Написать `AGENTS.md` по шаблону, 40–60 строк. Других файлов правил не создавать.
4. Прогнать чеклист.

**Чистка существующего.**
1. Посчитать `wc -l -c` по всем `AGENTS.md`, `CLAUDE.md` и `.claude/rules/*` в папке и выше.
2. Разметить каждую строку: маршрут, граница, поведение или «уходит» по таблице выше. Показать разметку пользователю до правок.
3. Если `AGENTS.md` и `CLAUDE.md` — два разных файла, собрать список правил, которые есть только в `CLAUDE.md`. Каждое из них найти в новом месте до удаления `CLAUDE.md`.
4. Перенести уходящие строки в их место; в файле оставить маршрут.
5. Разобрать `.claude/rules/` по разделу «Что скилл создаёт».
6. Убрать дубли между корнем и вложенными файлами.
7. Поправить ссылки на удалённые файлы в скиллах, README и вложенных `AGENTS.md`.
8. Прогнать чеклист.

## Чеклист

- [ ] В папке один файл правил `AGENTS.md`; `CLAUDE.md` и `.claude/rules/` нет (кроме симлинка для старых версий Claude Code)
- [ ] Каждая строка: маршрут, граница или постоянное поведение
- [ ] Нет процедур с шагами и истории решений
- [ ] Старт 40–60 строк; потолок 200 строк и 32 КБ; самая длинная цепочка меньше 32 768 байт
- [ ] Для каждого вложенного `AGENTS.md` в корне есть строка-маршрут
- [ ] Отдел первой строкой ведёт в штаб, путь существует
- [ ] Жёсткие запреты стоят в настройке харнеса, строка в файле только дублирует их для ясности
- [ ] Ни одно правило из удалённого `CLAUDE.md` не потерялось
- [ ] Смоук: новая сессия в папке без инструментов называет правило из файла; сессия во вложенной папке называет правило вложенного файла
