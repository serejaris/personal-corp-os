# Daily

**Отдел** — единица штаба со своими задачами: папка или репозиторий, на который ссылается файл правил штаба. Если в файле правил штаба они названы проектами, это те же отделы.

Каждый запуск читает задачи заново из источников. Файл дня — срез со ссылками; задача живёт в своём источнике.

## Шаги

1. Определи сегодняшнюю дату из системного времени.
2. Прочитай файл правил штаба (`CLAUDE.md` или `AGENTS.md` в корне штаба). Найди:
   - строки, где лежат задачи отделов, например `Обучение: ../corp-learn. Задачи отдела лежат в ../corp-learn/tasks/.` или `Задачи всех отделов — GitHub Project 3, owner my-handle.`;
   - раздел «Правила приоритета»: что важнее, сколько дел брать на день, какие колонки или лейблы значат «ждёт решения человека».
3. Строк о том, где лежат задачи, нет: остановись, скажи об этом и предложи дописать по строке на отдел в формате выше. Дальше иди только по путям, которые записаны в файле правил.
4. Прочитай задачи каждого отдела из его источника:
   - **файлы**: `tasks/*.md` отдела, кроме `README.md` и `_template.md`;
   - **GitHub Project (доска)**: `gh project item-list <N> --owner <owner> --format json --limit 200`; у каждой карточки-issue вне колонки `Done` возьми состояние и тело через `gh issue view <content.url> --json state,body,labels,updatedAt`;
   - **GitHub Issues без доски**: `gh issue list --repo <owner/repo> --state open --json number,title,url,body,labels,updatedAt`.
   Источник не читается: запиши отдел в «Не прочитано» с причиной.
5. Отбрось закрытые задачи. Задача **закрыта**:
   - в файле — статус «принято», «завершена» или «снята»;
   - на доске — колонка `Done` или issue в состоянии `CLOSED`;
   - в issues — состояние `CLOSED`.
6. По каждой открытой задаче возьми поля:

   | Поле | Файл `tasks/*.md` | Issue и карточка доски |
   |---|---|---|
   | состояние | раздел «Текущее состояние» | строка `**Status:**` в теле, иначе колонка доски |
   | следующий шаг | раздел «Следующий шаг» | строка `**Next:**` в теле |
   | ждёт решения человека | раздел «Результат и решение человека», если там вопрос к человеку | колонка или лейбл, которые «Правила приоритета» называют ожиданием решения |
   | срок | строка со сроком в файле | поле даты карточки или W-label |

   Поля нет в источнике: пиши «не указано».
7. Разложи задачи по разделам файла дня, каждую ровно в один: «Ждёт решения человека», «Просрочено или заблокировано», «В работе», «Остальное открытое». Внутри раздела порядок по «Правилам приоритета».
8. Выбери дела на сегодня для раздела «Сегодня»: столько, сколько велят «Правила приоритета». «Правил приоритета» нет — раздел «Сегодня» пропусти.
9. Запиши файл дня в штабе `tasks/<ГГГГ-ММ-ДД>.md`, папку `tasks/` создай при необходимости. Файл дня уже есть: замени срез задач, заметки человека оставь как есть.

## Файл дня

```markdown
# ГГГГ-ММ-ДД

## Сегодня
- <отдел> · <задача>: <следующий шаг> · <ссылка>

## Ждёт решения человека
- <отдел> · <задача>: <какое решение нужно> · [файл](../../corp-learn/tasks/<файл>.md)

## Просрочено или заблокировано
- <отдел> · <задача>: <срок или блокер> · <ссылка>

## В работе
- <отдел> · <задача>: <следующий шаг> · <ссылка>

## Остальное открытое
- <отдел> · <задача>: <состояние> · <ссылка>

## Не прочитано
- <отдел>: <причина>
```

Ссылки на файлы относительные от файла дня, на issue — URL. Пишутся только непустые разделы.

## Ответ в чат

До 7 строк: что ждёт решения человека, дела на сегодня, путь к файлу дня. Есть непрочитанные отделы — одна строка о них. «Правил приоритета» в файле правил штаба нет — одна строка об этом с предложением завести их через скилл `grill-me`.

## Границы

- Задачи отделов только читаешь; пишешь один файл — файл дня.
- Задачи, сроки и пути берёшь из источников как есть.
- Вопросы человеку задаёшь после того, как файл дня записан и ответ в чат дан; исключение — остановка на шаге 3.
