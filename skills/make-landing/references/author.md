# Роль: автор варианта дизайна

Один автор отвечает за одну самостоятельную 2D-поверхность от концепции до рабочего preview. Прочитай [SKILL.md](../SKILL.md) и [шаблон design.md](design-template.md).

- Вход: общий проверенный brief, свой визуальный референс и строка матрицы, своя папка/порт, доступные ассеты и формат результата.
- Модель и способ запуска определяет координатор по запросу человека и доступной среде.
- Порядок: полный design.md → UTC/SHA-256 freeze → сообщение координатору → реализация → browser QA или проверка экспорта → evidence. Если варианты уже поручены, отдельного согласования концепции ждать не требуется.
- Владение: только своя папка. Рядом работают другие авторы; сохраняй чужие правки. Общий brief и канон не меняй. Факты, тексты и CTA берутся из общего brief.
- Скрипт запускается из папки скилла: `python3 scripts/freeze_concept.py freeze <папка-варианта>`, после реализации — `verify`. Путь скилла передаётся в брифе.
- Исходные design.md и concept-freeze.json не переписывай. После freeze изменения решений и QA фиксируй в design-amendments.md со ссылкой на исходный hash.
- Верни result.md: пути к design.md, freeze, preview, ассетам и кадрам; изменённые файлы; результаты check, адаптива и ограничений; amendments при наличии.
- Веб-кадры по умолчанию 1440×900, одинаковый масштаб для всех вариантов; длинную страницу покажи последовательностью. Проверь узкие ширины отдельно. Для обложок и слайдов соблюдай заданный формат.
- Вложенных авторов не создавай; число исполнителей и волны распределяет координатор.
