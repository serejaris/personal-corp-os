## Библиотека

Правила лежат в скиллах Мэтта, этот файл держит порядок работы. Скилл читаешь целиком до того, как по нему работать или говорить, что он делает.

| Работа | Скилл |
|---|---|
| вычитка | `productivity/writing-for-agents`; документ — скилл: ещё `SKILL-MECHANICS.md` из той же папки |
| спор о термине в вычитке | `engineering/domain-modeling` |
| маршрут | `engineering/ask-matt` |
| шаг маршрута | скилл этого шага, его называет `ask-matt` |

Установленную копию находит первая команда. Копии нет: текст из репозитория берёт вторая, путь там `skills/<группа>/<скилл>/SKILL.md`.

## Вычитка

Вход — один документ для агента: `AGENTS.md`, `CLAUDE.md`, скилл, файл агента. Вызов называет папку с правилами целиком: сначала скилл плагина `audit-agent-rules`, он меряет размер файлов и ссылки между ними, вычитка идёт после него по одному документу.

1. Прочитай `writing-for-agents` по разделу «Библиотека».
2. Прочитай документ целиком и каждый файл, на который он ссылается.
3. Собери таблицу терминов: понятие и все слова, которыми документ его называет.
4. Пройди три проверки по каждому разделу документа.
5. Пройди остальные разделы `writing-for-agents`: нарушение идёт находкой с проверкой «прочее».
6. Отдай отчёт. Вычитка закончена, когда прочитан каждый раздел документа и в отчёте по каждой из трёх проверок стоят находки или «чисто».

| Проверка | Находка | Правка |
|---|---|---|
| Синонимы | одно понятие названо двумя словами; одно слово называет два понятия | одно слово на понятие во всём документе и в файлах, на которые он ссылается |
| Тавтология | одно значение записано дважды: в документе, в двух документах, в документе и в окружении — конфиге, выводе `--help`, структуре папок | одно место остаётся, остальные становятся ссылкой на него или уходят |
| Противоречия | два места требуют разного; шаг делает то, что правило запрещает; пример расходится с правилом | вопрос человеку: оба места и какое из них верно |

Синонимы и тавтологию `writing-for-agents` разбирает в разделах Leading words, Context pointers и Pruning. Противоречия он отдельно не называет: чаще всего это тавтология, копии которой разошлись.

### Отчёт

```markdown
**Вычитка `skills/post/SKILL.md`.** Строк: 120. Синонимы: 2, тавтология: 1, противоречия: 1, прочее: 1.

Термины

| Понятие | Слова в документе | Оставить |
|---|---|---|
| текст до публикации | «черновик», «драфт», «заготовка» | «черновик» |

Находки

| # | Где | Проверка | Было | Стало |
|---|---|---|---|---|
| 1 | `SKILL.md:14`, `:52` | синонимы | «драфт», «заготовка» | «черновик» |
| 2 | `SKILL.md:30`, `:88` | тавтология | правило о длине поста записано дважды | `:30` остаётся, `:88` удалить |
| 3 | `SKILL.md:41`, `:77` | противоречия | «публикуй сразу» и «жди подтверждения» | какое из двух верно? |
| 4 | `SKILL.md:9` | прочее | «будь внимателен» | удалить: модель делает это и без фразы |
```

Таблица терминов держит понятия с двумя и более словами и слова с двумя и более понятиями. Находка называет `файл:строка`, текст «было» и готовый текст «стало» или слово «удалить»; у противоречия «стало» — вопрос с двумя вариантами.

### Правка

Вызов говорит «правь»: вносишь в документ находки по синонимам, тавтологии и «прочему», противоречия оставляешь вопросами в отчёте. После правки проходишь пункты 2–5 вычитки по новому тексту. Без слова «правь» отдаёшь отчёт, документ остаётся как был.

## Маршрут

Маршрут лежит в `ask-matt`: основной путь от идеи до вливания, въезды для очереди чужих issues, трудного бага и большого туманного проекта, словари, границы фаз.

1. Из вызова неясно, что на руках: задай один вопрос — идея, баг, очередь чужих issues или большой туманный проект, и есть ли репозиторий.
2. Прочитай `ask-matt` по разделу «Библиотека».
3. Назови маршрут: шаги по порядку, на каждый строка «зачем».
4. Назови первый шаг и как его вызвать. У человека скиллы Мэтта не установлены: дай команды из раздела «Установка».

Часть шагов есть и в Personal Corp OS:

| Шаг маршрута | Скилл плагина |
|---|---|
| допрос замысла | `grill-me` |
| спецификация из разговора | `to-prd` |
| нарезка на сквозные срезы | `to-issues` |
| вехи с артефактом и воротами человека | `sdlc-milestones` |


```bash
codex plugin marketplace add mattpocock/skills
codex plugin add mattpocock-skills@mattpocock
```

После установки один раз на репозиторий запускают `/setup-matt-pocock-skills`. Он спрашивает, какой трекер задач используется, какие метки ставит `triage` и куда класть документы. Без этого шага `triage`, `to-spec`, `to-tickets` и `implement` не знают, куда писать.

## Правила

- Скиллы Мэтта пересказываешь своими словами. Его мнение приводишь ссылкой на скилл, статью или пост.
- Код пишут шаги маршрута. Ты называешь шаг и правишь только документ из вызова.
- Ответа в скиллах нет: говоришь «в скиллах этого нет» и называешь ближайший шаг.
