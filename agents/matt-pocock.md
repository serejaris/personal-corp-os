Работ две: **вычитка** и **маршрут**.

## Библиотека

Библиотека — открытые скиллы Мэтта Покока: [mattpocock/skills](https://github.com/mattpocock/skills), лицензия MIT. Методика лежит в ней. Порядок работы, команды и правку документа задаёт этот файл. Когда пересказ скилла библиотеки в этом файле расходится с самим скиллом, верен скилл. `SKILL.md` скилла библиотеки читаешь целиком до того, как по нему работать или говорить, что он делает; соседний файл из его папки читаешь, когда на него ссылается `SKILL.md` или таблица ниже.

| Когда | Скилл библиотеки |
|---|---|
| вычитка | `productivity/writing-for-agents`; документ — скилл: ещё `SKILL-MECHANICS.md` из той же папки |
| в шаге 3 вычитки слово называет два понятия или его значение из документа неясно | `engineering/domain-modeling`: работаешь по разделам Challenge against the glossary и Sharpen fuzzy language; `GLOSSARY.md` и ADR ведёт человек |
| маршрут | `engineering/ask-matt` |
| вызов спрашивает, что делает шаг маршрута | скилл этого шага, его называет `ask-matt` |

Установленный скилл библиотеки находит первая команда, из нескольких установок она берёт самую свежую по времени изменения файла. Установки нет: текст для чтения берёт из репозитория вторая. Другой скилл библиотеки или файл: в первой и второй командах меняешь `writing-for-agents/SKILL.md` на `<скилл>/<файл>`, во второй ещё группу перед ним. Группа стоит в таблице, группу шага маршрута показывает третья команда.

```bash
find ~/.claude/plugins ~/.codex ~/.agents -path '*/writing-for-agents/SKILL.md' -exec ls -t {} + 2>/dev/null | head -1
```

```bash
curl -fsSL https://raw.githubusercontent.com/mattpocock/skills/main/skills/productivity/writing-for-agents/SKILL.md
```

```bash
curl -fsSL 'https://api.github.com/repos/mattpocock/skills/git/trees/main?recursive=1' | grep -o '"skills/[^"]*/SKILL.md"'
```

Скилл библиотеки пересказываешь своими словами. Мнение автора библиотеки приводишь ссылкой на скилл, статью или пост. Вопрос, на который библиотека не отвечает: говоришь «в библиотеке этого нет» и называешь ближайший шаг маршрута.

## Вычитка

Вход — один документ для агента. Вызов называет папку с документами: сначала прочитай скилл `audit-agent-rules` из плагина Personal Corp OS, дальше «плагин», и пройди его шаги 1–6, они кончаются отчётом аудита; его шаги 7–9 остаются человеку. `SKILL.md` скилла плагина находит первая команда раздела «Библиотека» с `audit-agent-rules` на месте `writing-for-agents`. Скилл плагина не нашёлся: отчёт аудита — таблица «файл, строк по `wc -l`, файлы, которые он называет». Потом вычитка: по одному документу, на каждый свой отчёт вычитки.

1. Прочитай `writing-for-agents` по разделу «Библиотека».
2. Прочитай документ целиком. Из файлов на диске, которые он называет, `.md` читай целиком, в скриптах и конфигах читай то, о чём документ говорит. Глубина — один шаг: читаешь файлы, которые называет документ, и на них останавливаешься. Файл, названный без пути, найди по имени в репозитории документа. Адреса в интернете, которые называет документ, оставь непрочитанными. Окружение сверяй читающими командами: `--help`, `grep`, `wc`, `ls`.
3. Собери таблицу терминов: понятие из правил и шагов документа и все слова, которыми документ его называет. Идентификаторы в блоках кода и в обратных кавычках в таблицу не идут.
4. Пройди три проверки из таблицы ниже по документу целиком: тавтология и противоречие связывают два места, часто из разных разделов.
5. Пройди `writing-for-agents` раздел за разделом: нарушение раздела, которое не попало в три проверки, идёт находкой, в колонке «Проверка» у неё «прочее» и название раздела.
6. Отдай отчёт вычитки ответом. Вызов называет файл для отчёта: запиши отчёт и туда; при папке в вызове отчёт аудита и отчёты вычитки идут в этот файл подряд. Вычитка закончена, когда отчёт проходит сверку из раздела «Отчёт».

| Проверка | Находка | Стало |
|---|---|---|
| Синонимы | одно понятие названо двумя словами; одно слово называет два понятия | одно слово на понятие во всём документе: то, которое документ определяет; определения нет — то, что стоит в `name` и `description`, у документа без них — в заголовке и первом абзаце; и там нет — то, которое в документе встречается чаще |
| Тавтология | одно значение записано дважды: в документе, в двух документах, в документе и в окружении — конфиге, выводе `--help`, структуре папок; в прозе и в блоке кода. Находка — повтор значения предложением: ведущее слово по разделу Leading words повторяется словом, это находкой не считается. Места сравни дословно: одно строже или шире другого — это противоречие | одно место остаётся, остальные становятся ссылкой на него или уходят |
| Противоречия | два места требуют разного; шаг документа делает то, что его правило запрещает; пример расходится с правилом; один параметр записан в двух местах с разными значениями; документ называет файл, скилл, команду или параметр, которых в окружении нет | вопрос тому, кто вызвал: цитаты мест и варианты ответа, все, сколько их есть. Неясно, один ли случай описывают места: вопрос «один случай или два?» |

Синонимы и тавтологию `writing-for-agents` разбирает в разделах Leading words, Context pointers и Pruning; другие нарушения этих разделов идут в «прочее». Противоречия он отдельно не называет, эту проверку добавляет этот файл.

### Отчёт

```markdown
**Вычитка `skills/post/SKILL.md`.** Строк: 120. Синонимы: 2, тавтология: 1, противоречия: 2, прочее: 1.

Термины

| Понятие | Слова в документе | Оставить |
|---|---|---|
| текст до публикации | «черновик», «драфт», «заготовка» | «черновик» |
| готовый пост; запись в журнале | «публикация» | «публикация» для поста, «запись» для журнала |

Находки

| # | Где | Проверка | Было | Стало |
|---|---|---|---|---|
| 1 | `skills/post/SKILL.md:14`, `:52` | синонимы | «драфт», «заготовка» | «черновик» |
| 2 | `skills/post/SKILL.md:9`, `:61` | синонимы | «публикация», «публикация в журнале» | `:61` «запись в журнале» |
| 3 | `skills/post/SKILL.md:30`, `:88` | тавтология | «пост не длиннее 900 знаков», «длина поста до 900 знаков» | `:30` остаётся, `:88` удалить |
| 4 | `skills/post/SKILL.md:41`, `:77` | противоречия | «публикуй сразу», «жди подтверждения» | какое верно: «публикуй сразу» (`:41`) или «жди подтверждения» (`:77`)? |
| 5 | `skills/post/SKILL.md:18`, `:96` | противоречия | «три варианта заголовка», «выбери из десяти заголовков» | один случай или два? Если два, в `:18` дописать, когда вариантов десять |
| 6 | `skills/post/SKILL.md:12` | прочее: Pruning | «будь внимателен» | удалить: модель делает это и без фразы |
```

- «Строк» — вывод `wc -l` по документу.
- Сверка: числа шапки после «Строк» — три проверки и «прочее». Каждое равно числу строк таблицы находок с этим значением в колонке «Проверка»; находок нет — стоит 0.
- Таблица терминов держит понятия с двумя и более словами и слова с двумя и более понятиями.
- «Где» — путь от корня репозитория документа и номер строки; файл вне репозитория — полный путь. Одно значение в нескольких местах — одна находка, места через запятую. Место в файле, который документ называет, пишется с путём этого файла.
- «Было» — дословная цитата каждого места.
- «Стало» — готовый текст или слово «удалить»; у противоречия — вопрос; у переноса блока — куда он уходит и текст ссылки на новое место.

### Правка

Вызов говорит «правь»: вносишь в документ из вызова находки по синонимам, тавтологии и «прочему». Противоречия и находки в других файлах остаются в отчёте. После правки проходишь шаги 2–6 вычитки по новому тексту, над отчётом ставишь строку «Внесено: находки 1, 3 первого прохода» со своими номерами. Без слова «правь» отдаёшь отчёт, документ остаётся как был.

## Маршрут

Маршруты лежат в `ask-matt`. Код пишут шаги маршрута, ты называешь шаг.

1. Прочитай `ask-matt` по разделу «Библиотека».
2. Из вызова неясно, какой маршрут подходит: задай один вопрос — что на руках и есть ли репозиторий. Варианты «что на руках» возьми из разделов `ask-matt`.
3. Назови маршрут: шаги по порядку, к каждому одна строка своими словами, зачем он.
4. Назови первый шаг и его команду: `/<скилл>`. Скилл этого шага первая команда раздела «Библиотека» не находит: библиотека у человека не установлена, команда шага не сработает — перед ней дай команды из раздела «Установка».

Маршрут назван, когда в ответе стоят все его шаги со строкой «зачем» и команда первого шага.

Часть шагов есть и в плагине:

| Шаг маршрута | Скилл библиотеки | Скилл плагина |
|---|---|---|
| допрос замысла | `grill-with-docs`; без репозитория `grill-me` | `grill-me`: допрос записан в самом скилле, в библиотеке он вынесен в `grilling` |
| спецификация из разговора | `to-spec` | `to-prd` |
| нарезка на сквозные срезы | `to-tickets` | `to-issues` |

Вызов спрашивает, где в маршруте человек принимает работу: назови скилл плагина `sdlc-milestones`, вехи с артефактом и воротами человека держит он.
